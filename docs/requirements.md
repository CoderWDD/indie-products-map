# 非官方独立产品灵感浏览器需求文档

## 1. 项目定位

本项目是一个基于 `1c7/chinese-independent-developer` 的非官方独立产品灵感浏览器。

核心目标用户是：想做个人产品但还没方向的人。

核心任务是：帮助用户理解别人怎么做产品，而不是简单浏览项目列表。

本项目不以盈利为目的，不做长期复杂运营，不做账户系统，不接管原项目维护权。

## 2. 核心原则

- 原项目仍是权威数据来源。
- 本站只做结构化展示、AI 分析和灵感浏览增强。
- 页面必须明确标注本站为非官方项目。
- 项目收录、修改应优先回到原 GitHub 仓库。
- AI 内容必须标注为推测或辅助分析，不代表事实判断。
- 不评价项目成功或失败。
- 不估算收入。
- 不展示用户规模推断。
- 不展示风险提示。

## 3. 页面需求

### 3.1 首页 `/`

首页主入口是产品模式地图，而不是普通项目列表。

首页包含：

- 全局搜索框。
- 基础统计。
- 产品模式卡片矩阵。

基础统计包含：

- 总项目数。
- 产品模式数量。
- 有 AI 分析项目数。
- 最近更新时间。

基础统计不展示可访问项目数。

产品模式卡片展示：

- 模式名称。
- 一句话说明。
- 项目数量。
- 代表项目。
- 图标。
- 颜色。

首页不额外设置精选项目区，代表项目由产品模式卡片承担。

### 3.2 项目列表页 `/projects`

项目列表页使用卡片网格。

项目列表页支持：

- 搜索。
- 多选筛选。
- 基础排序。

默认排序沿用原 README 顺序。

排序支持：

- 默认。
- 项目名。
- 最近检测。
- 来源顺序。

筛选维度：

- 产品模式。
- 目标用户。
- 产品类型。
- 商业化方式。
- 链接状态弱筛选可以保留，但不突出。

筛选逻辑：

- 同一维度内使用 OR。
- 不同维度之间使用 AND。
- 搜索结果再应用筛选。

搜索范围：

- 项目名。
- 作者。
- 原始简介。
- AI 摘要。
- 标签。
- 产品模式。

搜索实现：

- 使用 Fuse.js。
- 支持普通模糊搜索。
- 不支持拼音搜索。

项目卡片展示：

- 项目名。
- 作者。
- 原始简介。
- AI 截断解读，约 60-80 字。
- 产品类型。
- 目标用户。
- 产品模式。
- 低置信度提示。
- 暂无 AI 分析提示。
- 弱化的外链按钮。

项目卡片不展示商业化标签，但商业化方式可用于筛选。

### 3.3 项目详情页 `/projects/[slug]`

每个项目必须有独立 URL。

slug 规则：

- 基于项目名生成。
- 冲突时追加短 hash。
- slug 生成后固化。
- 项目名变化时 URL 不变。

项目详情页展示：

- 原始项目信息。
- 项目官网链接。
- 原 GitHub 收录来源链接。
- 去原仓库提交或修改项目的入口。
- AI 分析。
- 目标用户。
- 产品类型。
- 产品模式。
- 可借鉴点，2-3 条。
- 灵感问题，2-3 条。
- 商业化推测。
- 同一产品模式下的相似项目。
- 链接状态。
- 最近检测时间。
- 分析依据。

项目详情页不展示：

- 风险提示。
- 成功或失败判断。
- 收入估算。
- 用户规模推断。
- 产品截图。
- 作者头像。

分析依据展示方式：

- 默认折叠。
- 展示 README 信息来源。
- 展示官网首页摘要。
- 如果官网不可访问，提示仅基于 README 推测。

### 3.4 产品模式页 `/patterns/[slug]`

每个产品模式必须有独立页面。

产品模式页展示：

- 模式名称。
- AI 生成的模式说明。
- 关键词。
- 图标和颜色。
- 项目数量。
- 代表项目，3-6 个。
- 该模式下全部项目。

代表项目选择规则：

- 由 AI 在聚类时选择并固化。
- 选择标准是能说明该产品模式且信息较完整。
- 代表项目不代表项目好坏。

### 3.5 关于页 `/about`

关于页必须包含：

- 本站是非官方项目。
- 数据来源说明。
- 原仓库链接。
- AI 分析边界说明。
- 如何去原仓库提交项目。
- 本站纠错或移除说明。
- 许可证说明。
- 最近更新时间。

纠错或移除通道：

- 提供 GitHub Issue 入口。
- 不做后台。
- 不做用户系统。

## 4. AI 分析需求

AI 用于中度产品理解，不只用于打标签。

每个项目 AI 生成：

- 简短摘要。
- 目标用户。
- 产品类型。
- 产品模式。
- 短文式产品解读，100-150 字。
- 可借鉴点，2-3 条。
- 灵感问题，2-3 条。
- 商业化方式推测。
- 商业化补充说明。
- 相似项目或同模式关联。
- 分析依据类型。
- 低置信度标记。

AI 不生成或不展示：

- 风险提示。
- 成功或失败判断。
- 收入估算。
- 用户量推断。
- 攻击性评价。
- 作者动机断言。

AI 分析语气：

- 产品顾问式。
- 中性、克制。
- 可启发，但不冒犯。
- 使用“可能”“看起来”“适合进一步验证”等表达。

事实与推测必须区分：

- 原始信息来自原 README 和官网。
- AI 分析是推测，仅供灵感参考。

低置信度提示：

- 只在低置信度时展示。
- 不展示高、中、低评分。
- 官网不可访问、内容太少、仅基于 README 时显示提示。

AI 输出要求：

- 严格 JSON Schema。
- 使用 Zod 校验。
- 校验失败自动重试 1-2 次。
- 仍失败则标记 AI 分析失败。
- 页面展示原始信息，并提示“AI 分析暂不可用”。
- 不在前端提供“AI 分析失败”筛选项。

不做：

- 人工覆盖机制。
- 敏感词或攻击性措辞检查流程。

但 prompt 必须约束语气。

## 5. 结构化字段

### 5.1 目标用户

目标用户使用固定枚举加 AI 补充说明。

允许多个，最多 3 个。

候选枚举：

- 开发者。
- 设计师。
- 内容创作者。
- 学生。
- 独立开发者。
- 小团队。
- 企业用户。
- 普通消费者。
- 产品经理。
- 运营人员。

### 5.2 产品类型

产品类型使用固定枚举。

允许多个，最多 3 个。

候选枚举：

- 网站。
- SaaS。
- 移动 App。
- 桌面 App。
- 浏览器插件。
- 小程序。
- 开源项目。
- 游戏。
- API / SDK。
- 内容站。
- 设计资源。
- 数据服务。

### 5.3 产品模式

产品模式由 AI 自动生成并固化，不使用固定枚举。

结构要求：

- 只有一层产品模式。
- 不做严格层级。
- 每个模式支持关键词。

增量聚类策略：

- 新项目优先由 AI 判断是否匹配已有产品模式。
- 匹配已有模式则加入。
- 无法匹配则进入“新发现”。
- 每月对“新发现”项目做一次批量聚类。
- 如果数量太少或不适合聚类，可以继续保留在“新发现”。
- 新生成的聚类固化到数据文件。

模式视觉：

- 每个产品模式有图标和颜色。
- 图标和颜色由 AI 建议并固化。
- 图标必须来自预设 Lucide Icons 集合。
- 颜色必须来自预设色板。

### 5.4 商业化方式

展示 AI 推测的商业化方式。

展示规则：

- 详情页展示。
- 列表页可筛选。
- 卡片上不直接显示。

商业化标签使用固定枚举加 AI 补充说明。

允许多个，最多 3 个。

候选枚举：

- 免费。
- 买断。
- 订阅。
- 广告。
- 赞助。
- 增值服务。
- API 计费。
- 企业服务。
- 未明确。

边界：

- 不展示是否已经盈利。
- 不估算收入。
- 不判断商业成功。
- 明确标注为 AI 推测。

## 6. 官网抓取与链接检测

AI 分析信息来源：

- README 原始信息。
- 项目官网首页内容。

官网打不开时：

- 基于 README 生成低置信度分析。
- 页面标注“仅基于原始简介推测，未访问官网”。

官网摘要：

- 单独保存。
- 不保存完整网页。
- 使用规则提取生成。
- 从 title、meta description、h1、主要段落中提取。
- 详情页默认折叠展示。

抓取限制：

- 单页面最多读取约 500KB 文本。
- 单请求超时约 10 秒。
- 最多跟随 3 次跳转。

链接检测和官网内容抓取分开记录：

- `linkStatus`。
- `homepageExtract`。

抓取失败需要记录原因：

- `timeout`。
- `dns_error`。
- `non_html`。
- `blocked`。
- `http_404`。
- `empty_content`。

链接状态：

- 每月检测所有项目。
- 详情页展示。
- 列表页弱提示。
- 首页统计不展示可访问项目数。
- 不单独设置失效项目入口。
- 搜索中不隐藏失效项目。

## 7. 数据更新机制

项目需要定期自动更新，不依赖手动触发。

更新方式：

- GitHub Actions 每月自动运行。
- 支持手动触发 `workflow_dispatch`。
- 每月中旬运行。
- 建议 cron 为 `20 3 15 * *`。
- 对应中国时间每月 15 日 11:20。

更新策略：

- 定期抓取原 README。
- 解析原始项目。
- 与已有数据对比。
- 识别新增项目。
- 识别删除项目。
- 识别原始信息变化项目。
- 新增项目立即 AI 分析。
- 原始信息变化项目不自动重跑 AI，只标记 AI 分析可能过期。
- 支持手动重新分析单个项目。
- 支持手动重新分析所有 stale 项目。
- 链接状态每月全量重检。
- 产品模式增量更新。

如果原 README 删除项目：

- 本站保留。
- 标记为“不在原列表中”。
- 不直接删除。

如果原始信息变化：

- 更新原始信息。
- 保留旧 AI 分析。
- 标记“原始信息已更新，AI 分析可能基于旧版本”。
- 不在月度流程自动重跑 AI。

更新失败：

- 不影响现有站点。
- 不提交部分结果。
- 旧站继续可用。
- 不额外做失败通知，依赖 GitHub Actions 自带状态。

GitHub Actions 流程：

```txt
更新数据
→ schema 校验
→ Vitest
→ Astro build
→ commit 到主分支
→ Vercel 自动部署
```

如果测试或构建失败：

- 不提交数据。

## 8. 数据文件

数据文件按领域拆分：

```txt
data/source-projects.json
data/projects.json
data/patterns.json
data/link-status.json
data/homepage-summaries.json
data/unclustered-projects.json
data/latest-update.json
```

文件说明：

- `source-projects.json`：原 README 解析快照。
- `projects.json`：增强后的项目数据。
- `patterns.json`：产品模式聚类。
- `link-status.json`：链接检测结果。
- `homepage-summaries.json`：官网首页摘要。
- `unclustered-projects.json`：新发现或待聚类项目。
- `latest-update.json`：最近一次更新日志。

开源仓库提交：

- AI 生成数据。
- 链接检测结果。
- 官网摘要。
- latest update 日志。

开源仓库不提交：

- 原始官网全文。
- API key。
- 私密配置。

## 16. 最终结论

本项目的合理形态是：用 Astro 做一个静态研究工具站，以原项目为数据源，用 AI 做产品理解、模式聚类和灵感启发；通过 GitHub Actions 每月自动增量更新，并由 Vercel 自动部署。

它不是新目录，也不是社区平台，而是一个低维护的独立产品灵感地图。
